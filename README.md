# crossy-visuals

Presentation and paper graphics for the Crossys — the crosswalk components of
[NFDI4Objects](https://www.nfdi4objects.net/): the Object Core Metadata
Profile (OCMDP), the Material Cultural Heritage Crosswalk Ontology (MaCHeCO)
and the Junction Node Layer (JNL) — and for the CrossyBase curation
environment. Generated by pure-Python scripts, no external CLI tools
required. Sibling repository to
[chublets-software/chublets-visuals](https://github.com/chublets-software/chublets-visuals)
and `FDOx-squirrel/fdox-visuals`, same house pattern, own palette.

Content authority: the [CrossyBase primer](https://github.com/crossy-graph)
(Gerber & Thiery). Structural reference for the first four blocks:
`data/raw/crossybase-figures/` — the seven Mermaid diagram sources of the
primer's own figures, vendored unchanged as the thing these scripts draw
*from*, not as something rendered directly.

## What this is

```
data/raw/crossybase-figures/*.mmd   structural reference (unchanged, read-only)
      │
      ▼  py/step_*.py                geometry + text, one module per block
      │
      ▼  main.py
img/<block>/*.svg                    source, versioned, grouped by block
      │
      ▼  resvg-py (in-process, no mmdc/Node/rsvg-convert needed)
img/<block>/*.png                    final graphics for slides, papers,
                                      READMEs — transparent background
```

Every graphic lives under a block subfolder, never directly in `img/`:

```
img/
├── block-1-crossy-architecture/    OCMDP / MaCHeCO / JNL as components in a
│                                   layered architecture (primer 4.1)
├── block-2-crosswalk-rules/        R1-R5 as a two-track rule cascade, plus
│                                   the correspondence-type vocabulary
│                                   (primer 3.6, 6)
├── block-3-jnl-junctions/          schema-level junction + three
│                                   instance-level junctions (primer 4.4)
├── block-4-crossybase-pipeline/    Curate -> Export -> Validate -> Publish
│                                   (primer 7)
├── system-architecture/            one consolidated bird's-eye diagram
└── source/                         Florian's raw reference graphics —
                                    visual reference, not a render input
```

`badge` = the small transparent icon alone (for slide corners, navigation).
`detail` = the diagram that actually explains the step; every `detail`
diagram carries the same badge icon plus a short header, so it stays visibly
tied to its badge (same convention as `chublets-visuals`).

**Block 1 — Crossy architecture** (primer 4.1): the three Crossys — OCMDP
(properties/edges), MaCHeCO (classes/nodes), JNL (the coupling) — in the
three-world architecture (metadata / research data / terminology) that feeds
the NFDI4Objects Knowledge Graph.

**Block 2 — Crosswalk rules & correspondence types** (primer 3.6, 6): the
metadata track (R3 → R4) and the ontology track (R1 → R2), R5's terminology
binding, the SHACL gate, and the match-type vocabulary itself
(`rdfs:subClassOf`/`owl:equivalentClass`, the SKOS match hierarchy,
`skos:exactMatch` vs. `owl:sameAs`).

**Block 3 — JNL junctions** (primer 4.4): the schema-level junction and its
three instance-level junctions — graph junction, terminology junction at
concept level, terminology junction at individual level — a four-part chain.

**Block 4 — CrossyBase pipeline** (primer 7): Curate (the five entity types
in the Wikibase) → Export (SPARQL CONSTRUCT + Python) → Validate (SHACL
R1–R5) → Publish (TS4NFDI/DANTE, the NFDI4Objects KG, project reuse).

**System architecture**: one diagram consolidating Blocks 1, 3 and 4 into
the single bird's-eye view — analogous to `chublets-software-architecture`.

All of Block 1–4 and the system diagram are **planned, not yet built** — see
`PRIMER.md` Teil B/C for status. This delivery is the repository skeleton
(step S1): layout, orchestrator, palette, vendored font, licensing. Content
lands step by step.

## Usage

```
pip install -r requirements.txt
python main.py
```

```
python main.py --list                 show the steps
python main.py --only block3          rebuild one block
python main.py --from block2          this step and everything after
python main.py --skip block4          everything but this
python main.py --dry-run              print the plan, run nothing
python main.py --strict               warnings become errors (what CI would run)
```

Running it twice produces byte-identical output; `git status` stays clean
after the second run (to be verified once a step draws real content — see
`PRIMER.md` Teil D).

## Design

Colour and symbol vocabulary live in one place, `py/visuals_utils.py` — every
step imports from there rather than repeating a hex code. `CROSSY_PURPLE`
(`#5b3fa0`) and `CROSSY_GOLD` (`#8a7420`) are the house colour pair; a
six-way `CATEGORY_COLORS` palette (component, metadata, domain, terminology,
validation, publication) covers grouped diagrams that need more than the two
house colours. The palette is not invented fresh: it is the `classDef`
scheme already shared by all seven `crossybase-figures` sources, formalised
rather than replaced.

Symbols follow the primer's own vocabulary (chapter 7.2: Terms are "the
edges", Entities are "the classes … the nodes") rather than an invented icon
set — see `SYMBOLS` in `py/visuals_utils.py`.

Typeface is [Fira Sans](https://github.com/mozilla/Fira) (Mozilla, SIL Open
Font License 1.1), vendored under `fonts/` (Regular + Medium) — a fresh clone
renders identically without the font being installed on the machine that
runs it.
